# img-rev — 图片反推工程师

**给一张图片，反推出它的风格、光线、镜头、调色与质感，并给出可复用的提示词。**

img-rev 是一个 Agent Skill（`SKILL.md` 格式）：它分析一张成品图，产出一份**逐项标注证据等级**的拆解报告——哪些是从画面里直接看出来的，哪些是合理推测，哪些凭成图根本判断不了。报告之后附视觉锚点和一段可直接复用的风格提示词（中英双语）。

它融合了两个开源项目的长处：[LunarXuan/image-prompt-reverse](https://github.com/LunarXuan/image-prompt-reverse) 的分析框架与证据纪律（内核），和 Zemon 的 `image-style-reverse-engineer` 的结构化报告层（14 维报告 + 5 色卡 + JSON 校验器）。关键改造：原报告层「每张图必须给出具体焦段 / 色温 / 胶片型号，否则校验失败」的强制规则被**证据分级**取代——没有证据的参数绝不许编。

---

## 四种模式

| 模式 | 什么时候用 | 产出 |
|---|---|---|
| **A · 提取报告**（默认） | 「拆一下这张图的风格和参数」 | 14 维逐项报告（每项标证据等级）+ 3–5 个视觉锚点 + 中英双语风格后缀提示词 |
| **B · 同图还原** | 「给我能重生成这张图的提示词」 | 中文还原提示词（450–700 字，锚点织入前 1/3）+ 英文等义版 + 10–15 条本图专属负面词 |
| **C · 只提风格** | 「只要风格，换个主体」 | 先列剥离清单（原图主体、身份、专属物件不带走），再给去主体化的风格档案 + 带 `[SUBJECT]` 占位的主提示词 + 分组负面词 |
| **D · 换人**（v1.2.0 定版） | 「把这张图里的人换成我上传的这位」 | **只出提示词**（图由其他模型生成）：两张图双权威（图 1 画布 / 图 2 身份，脸取点名的一格）、尺寸按图 1 实测、五件词形（保留式骨架 + key change 句 + 指代式特征点 + 融合句 + 编号引用）；成图带回后双脸裁图并排验收（分数 + 迁过来 / 丢掉清单） |

### D 模式为什么单开一节

换人会以其他模式不会遇到的方式失败，以下规则来自两轮真实实证（山茶花创始轮三版迭代；黄昏窗边系列同图十余版、跨两个生成模型对照）：

- **只出提示词**：D 模式的交付物是换脸提示词，图由用户拿其他模型生成；本技能负责出词，以及成图带回后的验收。
- **两张图、双权威不许混**：Image 1 是画布与场景权威（构图、服装、发型、道具、姿势、光、调色全归它）；Image 2 是身份权威，脸只取它被点名的那一格（近景格或半身人像格），不取整板。不再单独喂近景裁图——两图与三图的单变量对照实测，裁图对像度无可测增益，只多一个竞争脸源。
- **尺寸按 Image 1**：量出 Image 1 的实际像素尺寸写进词里（如 1908×956），成图尺寸与它一致；不写，生成端会自行改画幅、裁掉构图。
- **词形五件**：①先用 maintaining / keeping 详述 Image 1 的骨架——描述是为保留，不是为重建（重做式复述三败的教训：原图脸混在重建清单里从未被排除）；②一句 `The key change is that...` 单独拎出换脸这一件事；③特征点只指代不描写——点名要迁移的部位（眼型、鼻子、唇形、表情气质）并写「她的」，不写长相形容词、不写任何脸型数值（减法对照实测：整段锚点与零锚点同分）；④融合句：与 Image 1 既有的肤色和光照无缝衔接；⑤结尾保留 Image 1 的光影与气氛并复述尺寸。词内引用一律编号 Image 1 / Image 2（或目标工具自己的文件标签），不用描述让模型猜图。
- **表情是明示选择**：默认让身份侧的表情气质随脸带入（实测涨像度），交付时须点明代价——可能冲淡原图情绪；用户说原图情绪是命门时翻转：只取特征部位、表情留 Image 1。任选其一都要写到唇齿级：露齿大笑会顶起脸颊、眯起眼睛，改写整张脸的几何（创始轮第 1 版栽于此）。
- **验收看裁图**：用户带成图回来后，把成图脸与 Image 2 取脸格的脸裁出来放大并排，给诚实分数、逐项报「迁过来的 / 丢掉的」，并核对成图实际尺寸对 Image 1 是否一致；不设数值及格线，最终像不像归用户眼睛。
- **三轮修订上限与天花板披露**：一份词最多改三轮；变量不动时明说天花板在哪——生成模型的身份迁移强度（同图同话在更强的生成器上明显更像，差距可以在工具不在词），或身份权威本身软（如定妆板近景系由远景照推想生成）——不无限改词。

## 证据分级（本技能的铁律）

报告里的每个数值、每条判断，必须属于且标明以下三级之一：

- **观察 observed** — 画面里直接可见或可测量的：构图、景别、可读的阴影方向、实测色值。
- **推测 inferred** — 由可见效果反推的：焦段、光圈、色温、光比、胶片 / LUT。**只能以推测出现，必须带波浪号或区间，并写明依据的可见效果**（如「背景压缩与虚化形态 → ~85mm, ~f/1.8–2.8」）。
- **未知 unknown** — 凭成图判断不了的：是实拍还是 AI 生成、具体设备型号、无证据的胶片型号。**如实写未知，不许拿推测填空。**

色卡固定 5 色 HEX，并标明来源：`eyeballed`（目测近似）或 `measured`（工具采样，注明工具；采样要取饱和核心点，区域平均会被高光洗淡）。

## 快速开始

### 安装

把整个 `img-rev` 文件夹放进你的 agent 的技能目录即可，例如：

- Muse：`~/workspace/custom-skills/img-rev/`
- 其他兼容 Agent Skills 规范的 agent：其 `skills/` 目录

`skill.yaml` 是 Muse 的注册卡；其他平台只读 `SKILL.md` 也可工作。

### 使用

把图片发给 agent 并说明意图即可，例如：

```text
用 A 模式拆这张图：风格、光、镜头、调色都要，给我报告和可复用的提示词。
```

```text
只要风格，不要原图的人物和服装，我要换我自己的角色资产（C 模式）。
```

```text
给我能 1:1 还原这张图的提示词，中英双语（B 模式）。
```

### JSON 报告与校验

任一模式都可要求输出 JSON，结构见 [`references/report-schema.json`](references/report-schema.json)。交付前用自带校验器验一遍（仅用 Python 标准库）：

```bash
python3 scripts/validate_report.py path/to/report.json
```

校验器会拦下：证据等级缺失、推测型参数写成裸精确值（如 `85mm f/1.4`、`5500K` 不带波浪号 / 区间）、色卡不足 5 色、C 模式缺风格档案、D 模式缺 swap_spec（身份来源 / 取脸格 / 图 1 实测尺寸 / 特征点不足 2 项 / 表情处理未标 / 缺 QA 分数与迁丢清单）等问题。示例报告在 [`examples/example_report.json`](examples/example_report.json) 与 [`examples/example_person_swap.json`](examples/example_person_swap.json)。

```text
img-rev/
├── SKILL.md                              # 技能本体：三模式流程 + 证据分级铁律
├── skill.yaml                            # Muse 注册卡
├── references/
│   ├── analysis-framework.md             # 14 维报告框架（含速查短表）
│   ├── category-guides.md                # 15+ 分类专项（人像 / 风景 / 插画 / 商品…）
│   ├── light-and-color-vocabulary.md     # 光色词表：色温、光比、光质、胶片感

├── scripts/
│   └── validate_report.py                # 报告校验器（stdlib only）
├── examples/
│   ├── example_report.json               # A 模式完整示例（通过校验）
│   └── example_person_swap.json          # D 模式完整示例（通过校验，数据取自下方实测）
├── SOURCES.md                            # 上游来源与融合说明
└── LICENSE                               # GPL-3.0
```

## 实测记录

建成当天的首跑（山茶花园汉服人像）：A 模式报告的色卡走 PIL 采样（`measured`），采样点取花瓣饱和核心而非区域平均；焦段与色温以推测区间给出。随后用同一张图的 C 模式把风格迁移到另一位人物资产（古代纱裙版），风格档案与构图规则完整迁移、原图主体零串入，报告 JSON 均通过自家校验器。

同日晚的 D 模式实证（即 v1.1.0 的来源）：把同一张山茶花人像的人物换成另一位人物资产的脸，共迭代三版——第 1 版模型自作主张大笑露齿、脸部几何被笑容改写，约 6 分；第 2 版锁死抿唇浅笑并把近景格脸部单独裁图作权威参考，升到约 7 分；第 3 版把脸型词压到最重，脸长仍未回来，实证「加词压不过姿势透视」的天花板。三版的验收均走双脸裁图并排比对，分数与迁丢清单记入 `examples/example_person_swap.json`（取第 2 版数据）。

次日下午的黄昏窗边系列把 D 模式推到 v1.2.0：同一组图（黄昏原图 + 黄裙定妆板）在两条管线上跑了十余版——重做式复述三败、编辑式直接替换两成、近景裁图单变量对照无增益、一句话指令与满结构词同图同管线对照证明差距在生成模型而非词；外部模型自写词的五点复盘（结构化保留、身份与场景分离、点名特征部位、无缝融合、文件名引用）被吸收。D 模式自此定版为只出提示词：两张图、脸取点名一格、尺寸按图 1、五件词形、判读归人眼。
